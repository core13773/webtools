About the Timestamp Converter

A Unix timestamp is the number of seconds that have elapsed since the Unix epoch, defined as 1970-01-01T00:00:00Z (UTC), excluding leap seconds. Because it is a single integer with no timezone, no locale, and no formatting ambiguity, it is the lingua franca for time in software — the format you will find in REST API responses, database columns, log files, message queues, and cron schedules. This converter translates a Unix timestamp into a human-readable date and back, in both directions, entirely in your browser.

How it works

The tool reads an integer and decides whether it is in seconds or milliseconds. Classic Unix time and MySQL's TIMESTAMP store seconds (a 10-digit number around 2020–2030), while JavaScript's Date.getTime() and Java's Instant use milliseconds (a 13-digit number). Feeding a 13-digit value where seconds are expected shifts the date by roughly 31,000 years, so the converter auto-detects magnitude by digit length and chooses the right unit. Internally it delegates to the browser's Date object, which represents every instant as a millisecond count from the epoch.

Two subtleties matter. First, the timestamp itself is always UTC; only the way you format it into year/month/day depends on a timezone. The same instant produces the same numeric timestamp in Seoul, London, and New York — what differs is the wall-clock string you render from it. Second, Unix time deliberately excludes leap seconds, so each UTC day is treated as exactly 86,400 seconds and the count advances linearly. The converter also accepts fractional seconds and emits ISO 8601 (YYYY-MM-DDTHH:mm:ss.sssZ) for round-tripping into any other system.

Common use cases

  • Decoding a 10- or 13-digit timestamp from an API response into a local time
  • Encoding a chosen date and time back into a Unix value for storage
  • Comparing two instants across timezones by their UTC timestamp
  • Debugging off-by-1000 bugs caused by mixing seconds and milliseconds
  • Generating exp or iat claims for short-lived tokens

Worked example

The Unix timestamp 1717200000 converts to the ISO 8601 instant:

2024-06-01T04:00:00.000Z

Converting it back is lossless — parsing that ISO string with the browser's Date object returns exactly 1717200000. Because the Z suffix pins the value to UTC, the round-trip is independent of the viewer's local timezone. If you instead used 1717200000000 (13 digits, milliseconds) the same logic yields the identical instant; only the assumed unit changes.

Frequently asked questions

What is a Unix timestamp?

A Unix timestamp counts the seconds that have elapsed since the Unix epoch, 1970-01-01T00:00:00Z, excluding leap seconds. It is a single integer that is timezone-independent and widely used by APIs, databases, and log files.

What is the difference between seconds and milliseconds?

Classic Unix time and MySQL store seconds (typically 10 digits around 2020–2030), while JavaScript Date.getTime and Java Instant use milliseconds (13 digits). Mixing them up shifts the date by a factor of 1000, so the tool auto-detects 10- versus 13-digit input.

Is a Unix timestamp affected by timezones?

No. The timestamp itself is always UTC-based. Only how you format it for display depends on the local timezone, so the same instant always produces the same numeric timestamp everywhere in the world.

What is the Year 2038 problem?

Signed 32-bit Unix time overflows on 2038-01-19T03:14:07Z, wrapping to a date in 1901. Systems that store time as a 64-bit integer, as JavaScript and Java do, are not affected.

Does this tool work offline?

Yes. All conversion runs in your browser through the native Date object, so timestamps are converted locally without contacting any server.

타임스탬프 변환기란?

Unix 타임스탬프는 Unix 에포크인 1970-01-01T00:00:00Z(UTC) 이후에 경과한 초 수입니다(윤초 제외). 단일 정수이며 시간대, 로캘, 형식 모호성이 없기 때문에 소프트웨어에서 시간을 표현하는 사실상의 공용어입니다 — REST API 응답, 데이터베이스 칼럼, 로그 파일, 메시지 큐, cron 스케줄에서 흔히 볼 수 있는 형식입니다. 이 변환기는 Unix 타임스탬프를 사람이 읽을 수 있는 날짜로, 또 그 반대로 양방향 변환하며, 모든 처리가 브라우저 안에서 이루어집니다.

작동 방식

이 도구는 정수를 읽어 초 단위인지 밀리초 단위인지 판별합니다. 전통적인 Unix 시간과 MySQL의 TIMESTAMP는 초를 저장하고(2020~2030 무렵에는 10자리), JavaScript의 Date.getTime()와 Java의 Instant는 밀리초를 사용합니다(13자리). 초를 기대하는 자리에 13자리 값을 넣으면 날짜가 약 31,000년쯤 어긋나므로, 변환기는 자릿수 길이로 크기를 판별해 알맞은 단위를 선택합니다. 내부적으로는 에포크 이후의 밀리초 수로 모든 순간을 표현하는 브라우저의 Date 객체에 위임합니다.

두 가지 세부 사항이 중요합니다. 첫째, 타임스탬프 자체는 항상 UTC이며, 연/월/일로 변환해 표시하는 방식만 시간대에 따라 달라집니다. 서울, 런던, 뉴욕 어디서든 같은 순간은 같은 숫자 타임스탬프를 가집니다 — 달라지는 것은 그 값에서 렌더링한 시계 문자열뿐입니다. 둘째, Unix 시간은 의도적으로 윤초를 제외하므로, 매 UTC 일을 정확히 86,400초로 취급하고 카운트가 선형으로 증가합니다. 이 변환기는 소수 초도 받아들이고, 어떤 다른 시스템으로도 되돌릴 수 있도록 ISO 8601(YYYY-MM-DDTHH:mm:ss.sssZ) 형태로 출력합니다.

  • 원하는 날짜와 시간을 다시 Unix 값으로 인코딩해 저장
  • UTC 타임스탬프로 시간대가 다른 두 순간 비교
  • 초와 밀리초를 혼용해 발생하는 1000배 오차 버그 디버깅
  • 수명이 짧은 토큰의 exp 또는 iat 클레임 생성

사용 예

Unix 타임스탬프 1717200000는 다음 ISO 8601 순간으로 변환됩니다:

2024-06-01T04:00:00.000Z

역방향 변환은 무손실입니다 — 이 ISO 문자열을 브라우저의 Date 객체로 파싱하면 정확히 1717200000을 반환합니다. Z 접미사가 값을 UTC로 고정하므로 이 왕복은 보는 사람의 로컬 시간대와 무관합니다. 대신 1717200000000(13자리, 밀리초)을 사용해도 같은 로직으로 동일한 순간이 나오며, 달라지는 것은 가정한 단위뿐입니다.

자주 묻는 질문

Unix 타임스탬프란 무엇인가요?

Unix 타임스탬프는 Unix 에포크인 1970-01-01T00:00:00Z 이후에 경과한 초 수입니다(윤초 제외). 시간대에 영향을 받지 않는 단일 정수이며 API, 데이터베이스, 로그 파일에서 널리 사용됩니다.

초와 밀리초의 차이는?

전통적인 Unix 시간과 MySQL은 초를 저장하고(2020~2030 무렵에 보통 10자리), JavaScript Date.getTime와 Java Instant는 밀리초를 사용합니다(13자리). 혼용하면 날짜가 1000배 어긋나므로 이 도구는 10자리와 13자리 입력을 자동으로 감지합니다.

Unix 타임스탬프는 시간대의 영향을 받나요?

아닙니다. 타임스탬프 자체는 항상 UTC 기준입니다. 표시용으로 변환하는 방식만 로컬 시간대에 따라 달라지므로, 같은 순간은 전 세계 어디서나 같은 숫자 타임스탬프를 가집니다.

2038년 문제란 무엇인가요?

부호 있는 32비트 Unix 시간은 2038-01-19T03:14:07Z에 오버플로되어 1901년 날짜로 되돌아갑니다. JavaScript와 Java처럼 시간을 64비트 정수로 저장하는 시스템은 영향을 받지 않습니다.

이 도구는 오프라인에서도 동작하나요?

네. 모든 변환은 브라우저에서 네이티브 Date 객체로 실행되므로, 타임스탬프는 서버와 통신하지 않고 로컬에서 변환됩니다.
