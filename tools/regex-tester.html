About the Regex Tester

A regular expression is a compact pattern language for matching, extracting, and replacing text. In JavaScript it lives on the RegExp object and powers everything from form validation and route matching to log scraping. This tester compiles your pattern against a sample string in real time, highlights every match, and lets you run a substitution — all in the browser, so patterns and input never leave your machine.

How it works

A pattern can be written two ways. A regex literal such as /\d+/g is delimited by forward slashes and compiled when the script loads. The constructor form new RegExp("\\d+", "g") takes a runtime string, which is essential when the pattern is assembled from variables — but you must double the backslashes because the string layer consumes one. After the closing slash (or as the second constructor argument) come flags: g for global (every match, not just the first), i for case-insensitive, m for multiline (^ and $ match line boundaries), s for dotAll (the dot matches newlines), u for full Unicode handling, and y for sticky (match anchored at lastIndex).

Several methods consume a compiled pattern: test() returns a boolean, exec() returns one match object with capture groups, String.match() returns the first match (or all matches with the g flag), String.matchAll() iterates every match with its groups, and String.replace() substitutes matched text. Capture groups — parenthesized sub-patterns — remember the substring they matched and surface it as $1, $2, and so on. Lookahead ((?=...), (?!...)) and lookbehind ((?<=...), (?<!...)) assert context without consuming characters, letting you match a token only when it is preceded or followed by something specific.

Common use cases

  • Validating emails, phone numbers, and other structured inputs
  • Extracting every URL, hashtag, or mention from a block of text
  • Scrubbing or redacting sensitive tokens from a log file
  • Building a replace call that reorders captured fields
  • Debugging why a pattern matches (or fails to match) before deploying it

Worked example

Pattern with two capture groups, tested against a sample string:

Pattern:  /(\w+)@(\w+\.\w+)/g
Flags:    g
String:   contact ada@example.com or bob@test.org

The engine finds two full matches and captures the local part and the domain of each:

Match 1: ada@example.com
  group 1 (local):   ada
  group 2 (domain):  example.com
Match 2: bob@test.org
  group 1 (local):   bob
  group 2 (domain):  test.org

With those groups you can run replace using $2 then $1 to swap their order — capture groups are what make a regex more than a yes/no test.

Frequently asked questions

What is the difference between a regex literal and the constructor?

A literal such as /abc/gi is compiled once when the script loads and needs no extra escaping of backslashes. The constructor new RegExp('abc', 'gi') accepts a runtime string, which is useful when the pattern is built from variables but requires you to double-escape backslashes in the source.

What do the common flags do?

g finds every match, i is case-insensitive, m makes ^ and $ match line boundaries, s lets the dot match newlines, u enables full Unicode handling, and y anchors each match at lastIndex. You can combine them, for example gi.

How do capture groups work?

Parentheses form a capture group that remembers the substring it matched. match and matchAll return the full match plus each group, replace can reference them as $1 and $2, and exec exposes them on the result array.

Are my inputs sent to a server?

No. Pattern compilation, matching, and substitution all run in your browser through the native RegExp engine. Patterns and test strings stay on your device.

정규식 테스터란?

정규식(Regular Expression)은 텍스트를 검사·추출·치환하기 위한 간결한 패턴 언어입니다. JavaScript에서는 RegExp 객체에 자리 잡고 있으며 폼 검증, 라우트 매칭, 로그 분석, 편집기의 찾기바꾸기까지 두루 쓰입니다. 이 테스터는 패턴을 샘플 문자열에 대해 실시간으로 컴파일해 모든 일치를 강조 표시하고 치환까지 실행할 수 있게 합니다 — 모두 브라우저 안에서 처리되므로 패턴과 입력이 기기를 떠나지 않습니다.

작동 방식

패턴은 두 가지 방식으로 작성할 수 있습니다. 슬래시로 감싼 정규식 리터럴 /\d+/g은 스크립트가 로드될 때 컴파일됩니다. 생성자 형태 new RegExp("\\d+", "g")는 런타임 문자열을 받으며, 변수로 패턴을 조립할 때 필수적입니다 — 다만 문자열 단계에서 백슬래시 하나를 소비하므로 두 개로 겹쳐 써야 합니다. 닫는 슬래시 뒤(또는 생성자의 두 번째 인자로)에 플래그가 옵니다. g는 전역(첫 일치가 아니라 모든 일치), i는 대소문자 무시, m은 멀티라인(^과 $가 줄 경계에 일치), s는 dotAll(점이 줄바꿈에도 일치), u는 완전한 유니코드 처리, y는 sticky(lastIndex에 고정해 일치)입니다.

컴파일된 패턴을 소비하는 메서드는 여럿입니다. test()는 불리언을 반환하고, exec()는 캡처 그룹을 포함한 일치 객체 하나를 반환하며, String.match()는 첫 일치(또는 g 플래그일 때 모든 일치)를, String.matchAll()는 각 일치와 그룹을 순회하고, String.replace()는 일치한 텍스트를 치환합니다. 캡처 그룹 — 괄호로 감싼 하위 패턴 —은 자신이 일치한 부분 문자열을 기억하고 $1, $2 식으로 노출합니다. 룩어헤드((?=...), (?!...))와 룩비하인드((?<=...), (?<!...))는 문자를 소비하지 않고 문맥을 단언하므로, 어떤 토큰이 특정 무언가의 앞(또는 뒤)에 있을 때만 일치시킬 수 있습니다.

  • 로그 파일에서 민감한 토큰을 스크럽하거나 마스킹하기

  • 패턴이 일치하는지(또는 실패하는지) 배포 전에 디버깅하기

사용 예

두 개의 캡처 그룹을 가진 패턴을 샘플 문자열에 대해 검사합니다:

패턴:  /(\w+)@(\w+\.\w+)/g
플래그: g
문자열: contact ada@example.com or bob@test.org

엔진은 두 개의 전체 일치를 찾고 각각의 로컬 파트와 도메인을 캡처합니다:

일치 1: ada@example.com
  그룹 1 (local):   ada
  그룹 2 (domain):  example.com
일치 2: bob@test.org
  그룹 1 (local):   bob
  그룹 2 (domain):  test.org

이 그룹들로 replace에서 $2와 $1을 써 순서를 바꾸거나 도메인만 뽑아낼 수 있습니다 — 캡처 그룹이 정규식을 단순한 예/아니오 검사 이상으로 만듭니다.

자주 묻는 질문

정규식 리터럴과 생성자의 차이는?

/abc/gi 같은 리터럴은 스크립트가 로드될 때 한 번 컴파일되며 백슬래시를 추가로 이스케이프할 필요가 없습니다. new RegExp('abc', 'gi') 생성자는 런타임 문자열을 받아 변수로 패턴을 만들 때 유용하지만, 소스에서 백슬래시를 두 번 써야 합니다.

주요 플래그는 무엇을 하나요?

g는 모든 일치를 찾고, i는 대소문자를 무시하며, m은 ^와 $가 줄 경계에 일치하게 하고, s는 점이 줄바꿈에도 일치하게 하며, u는 완전한 유니코드 처리를 켜고, y는 lastIndex에 일치를 고정합니다. gi처럼 조합할 수 있습니다.

캡처 그룹은 어떻게 동작하나요?

괄호는 자신이 일치한 부분 문자열을 기억하는 캡처 그룹을 만듭니다. match와 matchAll은 전체 일치와 각 그룹을 반환하고, replace는 $1과 $2로 참조할 수 있으며, exec는 결과 배열에 노출합니다.

입력이 서버로 전송되나요?

아닙니다. 패턴 컴파일, 일치, 치환은 모두 브라우저에서 네이티브 RegExp 엔진으로 실행됩니다. 패턴과 테스트 문자열은 기기에 머뭅니다.
