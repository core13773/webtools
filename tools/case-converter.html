About the Case Converter

The Case Converter rewrites a string into the casing convention a given language or framework expects. Different ecosystems settled on different rules: JavaScript variables are camelCase, Python variables are snake_case, CSS classes and URLs are kebab-case, and C constants are CONSTANT_CASE. Pasting the wrong casing into a file either fails a linter or breaks naming conventions silently, so a one-click converter saves real friction when moving text between contexts.

How it works

The core casing primitives are JavaScript's toLowerCase() and toUpperCase(), which apply Unicode default case mapping. Building the multi-word conventions on top requires a word-boundary detector: the converter splits input on spaces, punctuation, and case transitions — a lowercase letter followed by an uppercase letter (as in myVar) is itself a boundary, so mixed-case identifiers can be re-emitted in any style. Each convention then rejoins the words differently:

  • camelCase — first word lowercase, every later word capitalized, no separator
  • PascalCase — every word capitalized, no separator
  • snake_case — all lowercase, words joined with _
  • kebab-case — all lowercase, words joined with -
  • CONSTANT_CASE — all uppercase, words joined with _
  • Title Case — every word capitalized, separated by spaces

Case mapping is locale-sensitive. The classic case is Turkish, whose alphabet distinguishes dotted and undotted I: the lowercase of I is ı (dotless) and the uppercase of i is İ (dotted). Default toLowerCase() ignores this, so for locale-correct output use toLocaleLowerCase('tr').

Common use cases

  • Turning a readable title into a camelCase JavaScript variable or function name
  • Generating snake_case identifiers for a Python or Ruby codebase
  • Producing kebab-case CSS class names and URL path segments
  • Normalizing database column or CONSTANT_CASE enum values
  • Converting SHOUTING text to readable Title Case

Worked example

Starting from the title Hello World Example, each convention produces a distinct identifier:

camelCase:       helloWorldExample
PascalCase:      HelloWorldExample
snake_case:      hello_world_example
kebab-case:      hello-world-example
CONSTANT_CASE:   HELLO_WORLD_EXAMPLE
Title Case:      Hello World Example

Notice that camelCase lowercases only the first word, while PascalCase capitalizes every word — the two differ solely in the treatment of the leading word.

Frequently asked questions

What is the difference between camelCase and PascalCase?

In camelCase the first word is lowercase and each following word starts uppercase, with no separators (for example myVariableName). PascalCase (also called UpperCamelCase) capitalizes the first word as well, so the same input becomes MyVariableName. camelCase is the JavaScript convention for variables; PascalCase is used for classes and React components.

How are words split apart?

Words are split on spaces, punctuation, and case transitions. A lowercase letter followed by an uppercase letter (for example myVar) is treated as a boundary, so the converter can turn mixed input into snake_case or kebab-case without manual separation.

When should I use snake_case versus kebab-case?

snake_case (underscores) is the convention in Python, Ruby, and database column names. kebab-case (hyphens) is preferred in URLs, CSS class names, and HTML data attributes because hyphens are URL-safe and never need escaping.

Is case conversion locale-dependent?

Yes. JavaScript toLowerCase and toUpperCase follow Unicode default case mapping, but some languages have special rules. The most famous is Turkish, where lowercase of I is ı (dotted) and uppercase of i is İ (dotless). Use toLocaleLowerCase with a locale argument when locale-specific output matters.

Does the tool send my text anywhere?

No. All conversions run in your browser through native string methods. Nothing is uploaded, so the tool is safe for code snippets, identifiers, and confidential content.

케이스 변환기란?

케이스 변환기는 문자열을 특정 언어나 프레임워크가 기대하는 대소문자 규칙으로 다시 써 줍니다. 생태계마다 정착한 규칙이 다릅니다. JavaScript 변수는 camelCase, Python 변수는 snake_case, CSS 클래스와 URL은 kebab-case, C 상수는 CONSTANT_CASE를 씁니다. 잘못된 케이스를 그대로 붙여 넣으면 린터가 걸리거나 명명 규칙이 조용히 깨지므로, 문맥을 옮길 때 한 번에 변환해 주는 도구가 실질적인 불편을 줄여 줍니다.

작동 방식

핵심 대소문자 프리미티브는 JavaScript의 toLowerCase()와 toUpperCase()이며, 유니코드 기본 케이스 매핑을 적용합니다. 여러 단어로 이루어진 규칙을 그 위에 올리려면 단어 경계 감지가 필요합니다. 이 변환기는 공백, 구두점, 그리고 대소문자 전환을 기준으로 입력을 분할합니다. 즉 소문자 뒤에 오는 대문자(예: myVar) 자체가 경계이므로, 섞여 있는 식별자도 어떤 스타일로든 다시 출력할 수 있습니다. 각 규칙은 단어를 서로 다르게 이어 붙입니다.

  • camelCase — 첫 단어는 소문자, 이후 단어만 대문자 시작, 구분자 없음
  • PascalCase — 모든 단어 대문자 시작, 구분자 없음
  • snake_case — 모두 소문자, 단어를 _로 결합
  • kebab-case — 모두 소문자, 단어를 -로 결합
  • CONSTANT_CASE — 모두 대문자, 단어를 _로 결합
  • Title Case — 모든 단어 대문자 시작, 공백으로 구분

케이스 매핑은 로케일에 따라 달라집니다. 대표적인 예가 터키어로, 알파벳이 점이 있는 I와 없는 I를 구분합니다. I의 소문자는 ı(점 없음), i의 대문자는 İ(점 있음)입니다. 기본 toLowerCase()는 이를 무시하므로, 로케일에 맞는 결과가 필요하면 toLocaleLowerCase('tr')를 사용해야 합니다.

자주 묻는 질문

camelCase와 PascalCase의 차이는?

camelCase는 첫 단어를 소문자로 시작하고 이후 단어만 대문자로 시작하며 구분자가 없습니다(예: myVariableName). PascalCase(UpperCamelCase라고도 함)는 첫 단어까지 대문자로 시작하므로 같은 입력이 MyVariableName이 됩니다. camelCase는 JavaScript 변수 관례이고 PascalCase는 클래스와 React 컴포넌트에 씁니다.

단어는 어떻게 분할하나요?

공백, 구두점, 그리고 대소문자 전환을 기준으로 단어를 분할합니다. 소문자 뒤에 오는 대문자(예: myVar)를 경계로 처리하므로, 섞인 입력도 수동 분리 없이 snake_case나 kebab-case로 바꿀 수 있습니다.

snake_case와 kebab-case는 언제 쓰나요?

snake_case(밑줄)는 Python, Ruby, 데이터베이스 컬럼명 관례입니다. kebab-case(하이픈)는 URL, CSS 클래스명, HTML data 속성에 선호되는데, 하이픈은 URL에 안전하고 이스케이프가 필요 없기 때문입니다.

케이스 변환은 로케일에 따라 달라지나요?

네. JavaScript의 toLowerCase/toUpperCase는 유니코드 기본 케이스 매핑을 따르지만 일부 언어에는 특별한 규칙이 있습니다. 가장 유명한 예가 터키어로, I의 소문자는 ı(점 있음), i의 대문자는 İ(점 없음)입니다. 로케일별 결과가 중요하면 로케일 인자를 넘겨 toLocaleLowerCase를 사용하세요.

제 텍스트가 외부로 전송되나요?

아닙니다. 모든 변환은 브라우저에서 네이티브 문자열 메서드로 처리됩니다. 업로드되는 것은 없으므로 코드 조각, 식별자, 기밀 내용에도 안전합니다.
