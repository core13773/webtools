About the Markdown Previewer

Markdown is a lightweight plain-text format that lets writers produce structured HTML without ever touching an angle bracket. It powers README files on GitHub, documentation sites, static-site generators, chat apps, and note-taking tools. This previewer takes the text you type, parses it into HTML in real time, and shows the rendered result side by side — so you see exactly how the published page will look while you write. Everything runs in your browser; no draft is ever uploaded.

How it works

The renderer targets CommonMark, the unambiguous specification of Markdown, layered with GitHub-Flavored Markdown (GFM) extras. The parser first tokenizes block-level constructs: headings (#, ##), ordered and unordered lists (1., -), fenced code blocks (triple backticks), blockquotes (>), thematic breaks, and paragraphs. It then resolves inline constructs inside each block: bold (**text**), italics (*text*), links ([text](url)), and inline code (single backticks). Each token becomes a corresponding HTML element, so Markdown is fundamentally a compiler from shorthand text to HTML.

GFM adds constructs that plain CommonMark lacks: pipe tables, task lists with [ ] / [x] checkboxes, and strikethrough with ~~text~~. Because the output is HTML that will live in a page, the rendered string is sanitized before insertion: raw <script> tags, inline event handlers such as onclick, and javascript: URLs are stripped. That sanitization is what prevents stored cross-site scripting (XSS) when user-authored Markdown is displayed — the single most important security property of any Markdown renderer.

Common use cases

  • Drafting a project README and previewing it before pushing to GitHub
  • Writing documentation that will be published as static HTML
  • Checking that tables, task lists, and code fences render correctly
  • Grabbing clean HTML to paste into a CMS or email template
  • Reviewing GFM-specific syntax that plain Markdown parsers miss

Worked example

Given this Markdown snippet:

# Release notes
- Added **dark mode**
- Fixed `login` redirect
> Ships in v2.0

The renderer compiles it to this HTML:

<h1>Release notes</h1>
<ul>
  <li>Added <strong>dark mode</strong></li>
  <li>Fixed <code>login</code> redirect</li>
</ul>
<blockquote>
  <p>Ships in v2.0</p>
</blockquote>

The heading, list, inline strong and code, and blockquote all map one-to-one from their Markdown shorthand.

Frequently asked questions

What flavor of Markdown does this support?

The renderer follows the CommonMark specification and adds GitHub-Flavored Markdown extras such as tables, task lists, strikethrough, and fenced code blocks. Together these cover the syntax most documentation and README files use.

Does Markdown compile to HTML?

Yes. Markdown is a plain-text shorthand. The parser tokenizes block and inline constructs and emits HTML elements, which the preview pane renders and the Copy HTML action lets you reuse elsewhere.

Is the rendered HTML safe from XSS?

The output is sanitized before it is inserted into the page, so raw script tags, inline event handlers, and javascript: URLs are stripped. You should still sanitize again if you embed the exported HTML into your own site, since trust boundaries differ.

Are my documents uploaded to a server?

No. Parsing, rendering, and HTML export all run locally in your browser. Drafts, notes, and any pasted content stay on your device.

What is the difference between block and inline Markdown?

Block constructs such as headings, lists, code fences, and blockquotes structure the document into elements. Inline syntax such as bold, italics, links, and inline code styles text within a paragraph. The parser handles each layer with its own rules.

Can I download the source Markdown?

Yes. The Download Markdown action saves the exact text in the input area as an .md file, preserving code fences, tables, and all formatting exactly as you wrote it.

마크다운 프리뷰어란?

마크다운은 작성자가 꺾쇠 괄호를 전혀 만지지 않고 구조화된 HTML을 만들 수 있게 해 주는 가벼운 일반 텍스트 형식입니다. GitHub의 README, 문서 사이트, 정적 사이트 생성기, 채팅 앱, 노트 앱까지 두루 쓰입니다. 이 프리뷰어는 입력한 텍스트를 받아 실시간으로 HTML로 파싱하고 렌더링 결과를 나란히 보여 줍니다 — 글을 쓰는 동안 게시될 페이지가 어떻게 보일지 정확히 볼 수 있습니다. 모든 처리는 브라우저에서 이루어지며 어떤 초안도 업로드되지 않습니다.

작동 방식

렌더러는 모호함 없는 마크다운 표준인 CommonMark를 대상으로 하며, 그 위에 GitHub-Flavored Markdown(GFM) 확장을 얹습니다. 파서는 먼저 블록 수준 구문을 토큰화합니다. 제목(#, ##), 순서/비순서 목록(1., -), 펜스 코드 블록(백틱 세 개), 인용구(>), 수평선, 단락 등입니다. 그다음 각 블록 안의 인라인 구문을 해석합니다. 굵게(**text**), 기울임(*text*), 링크([text](url)), 인라인 코드(백틱 하나)입니다. 각 토큰은 대응하는 HTML 요소가 되므로, 마크다운은 본질적으로 약어 텍스트에서 HTML로 가는 컴파일러입니다.

GFM은 일반 CommonMark에 없는 구문을 추가합니다. 파이프 테이블, [ ] / [x] 체크박스 작업 목록, ~~text~~ 취소선입니다. 출력이 페이지에 들어갈 HTML이므로, 렌더링된 문자열은 삽입 전에 새니타이즈됩니다. 날것의 <script> 태그, onclick 같은 인라인 이벤트 핸들러, javascript: URL이 제거됩니다. 이 새니타이징이 사용자가 작성한 마크다운을 표시할 때 저장형 XSS(크로스사이트 스크립팅)를 막아 주며 — 모든 마크다운 렌더러에서 가장 중요한 보안 속성입니다.

  • 정적 HTML로 게시될 문서 작성하기
  • 테이블, 작업 목록, 코드 펜스가 올바르게 렌더링되는지 확인하기
  • CMS나 이메일 템플릿에 넣을 깨끗한 HTML 가져오기
  • 일반 마크다운 파서가 놓치는 GFM 전용 구문 검토하기

자주 묻는 질문

어떤 마크다운 변형을 지원하나요?

렌더러는 CommonMark 사양을 따르며 테이블, 작업 목록, 취소선, 펜스 코드 블록 같은 GitHub-Flavored Markdown 확장을 추가합니다. 이 조합이 대부분의 문서와 README에서 쓰는 구문을 다룹니다.

마크다운이 HTML로 컴파일되나요?

네. 마크다운은 일반 텍스트 약어입니다. 파서가 블록과 인라인 구문을 토큰화하여 HTML 요소를 만들어 내며, 미리보기 창이 그것을 렌더링하고 Copy HTML 동작으로 다른 곳에 재사용할 수 있습니다.

렌더링된 HTML이 XSS에 안전한가요?

출력은 페이지에 삽입되기 전에 새니타이즈되므로 날것의 script 태그, 인라인 이벤트 핸들러, javascript: URL이 제거됩니다. 다만 내보낸 HTML을 자신의 사이트에 삽입할 때는 신뢰 경계가 다르므로 다시 새니타이즈하는 것이 좋습니다.

문서가 서버로 업로드되나요?

아닙니다. 파싱, 렌더링, HTML 내보내기는 모두 브라우저에서 로컬로 실행됩니다. 초안, 메모, 붙여넣은 모든 콘텐츠는 기기에 머뭅니다.

블록 마크다운과 인라인 마크다운의 차이는?

제목, 목록, 코드 펜스, 인용구 같은 블록 구문이 문서를 요소로 구조화합니다. 굵게, 기울임, 링크, 인라인 코드 같은 인라인 구문은 단락 안의 텍스트를 꾸밉니다. 파서는 각 계층을 자체 규칙으로 처리합니다.

원본 마크다운을 다운로드할 수 있나요?

네. Download Markdown 동작이 입력 영역의 텍스트를 그대로 .md 파일로 저장하며, 코드 펜스, 테이블, 모든 서식이 작성한 그대로 보존됩니다.
