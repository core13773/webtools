About the Text Counter

The Text Counter measures a string across four axes — characters, words, lines, and bytes — updating in real time as you type. Each axis answers a different question, which matters whenever limits are involved: a tweet is bounded by character count, an essay by word count, a source file by line count, and a network payload by byte count.

How it works

The character count uses the JavaScript String.prototype.length property, which returns the number of UTF-16 code units — not the number of visible symbols. Most text fits in a single code unit (one per ASCII letter, one per common CJK ideograph), but any code point above U+FFFF is encoded as a surrogate pair of two code units. That is why an emoji such as 😀 reports .length === 2 even though a reader perceives one glyph. To count what humans actually see — grapheme clusters, which also cover Hangul jamo combinations and emoji joined with a Zero-Width Joiner (ZWJ) — you need Intl.Segmenter with the grapheme granularity.

Words are split on the regular expression /\s+/ and the non-empty segments are counted. Lines are split on \n. Bytes come from TextEncoder, which encodes the string as UTF-8: ASCII takes 1 byte, Latin-1 letters take 2, Hangul syllables take 3, and most emoji take 4. Everything runs locally in the browser.

Common use cases

  • Checking length against a tweet limit of 280 characters or a meta description of ~155
  • Counting words for essays, abstracts, and cover letters with a fixed quota
  • Measuring the UTF-8 byte size of a payload before sending it over a network
  • Estimating reading time at roughly 200–250 words per minute
  • Verifying line counts when a style guide caps file length

Worked example

Take the string Hi 안녕 😀 (a space, two ASCII letters, a space, two Hangul syllables, a space, and one emoji). The counts come out as follows:

Characters (.length):     8   // H,i,space,안,녕,space,surrogate-pair
Bytes (UTF-8):           13   // 2 + 1 + 6 + 1 + 4
Words (\s+ split):        3   // "Hi", "안녕", "😀"
Lines (\n split):         1
Graphemes (Segmenter):    6   // what the user sees

Notice the gap between .length (8) and graphemes (6): the surrogate pair collapses into one perceived character, so a strict .length check misreports emoji text.

Frequently asked questions

Why does an emoji count as two characters?

JavaScript strings are stored as UTF-16, and the .length property counts code units, not visible symbols. Characters outside the Basic Multilingual Plane (such as emoji) are encoded as a surrogate pair of two code units, so .length reports 2. A grapheme counter using Intl.Segmenter reports 1 because it counts what a user perceives as a single character.

How are words counted?

Words are counted by splitting the text on one or more whitespace characters (the regular expression /\s+/), then counting the non-empty segments. Punctuation attached to a word is not stripped, so hello, counts as one word.

What is the difference between characters and bytes?

Characters counts UTF-16 code units via string .length. Bytes counts the size of the UTF-8 encoding using TextEncoder. An ASCII letter is 1 byte, a Korean Hangul syllable is typically 3 bytes, and an emoji is usually 4 bytes.

How are lines counted?

Lines are counted by splitting the input on the newline character (\n). An empty input reports 0 lines, while a single line with no trailing newline reports 1.

Is my text uploaded to a server?

No. Every count is computed locally in your browser as you type. The text never leaves your device, so the tool is safe for drafts, messages, and sensitive content.

텍스트 카운터란?

텍스트 카운터는 문자열의 크기를 문자, 단어, 줄, 바이트라는 네 가지 기준으로 측정하며, 입력할 때마다 실시간으로 갱신합니다. 각 기준은 서로 다른 질문에 답하므로 글자 수 제한이 걸린 상황에서 의미가 있습니다. 트윗은 문자 수로, 에세이는 단어 수로, 소스 파일은 줄 수로, 네트워크 페이로드는 바이트 수로 제한됩니다. 내 상황에 어떤 기준이 해당하는지 아는 것이 이 도구 활용의 절반입니다.

작동 방식

문자 수는 JavaScript의 String.prototype.length 속성을 사용하며, 이것은 보이는 기호의 개수가 아니라 UTF-16 코드 단위(code unit)의 개수를 반환합니다. 대부분의 텍스트는 코드 단위 하나로 표현됩니다(ASCII 글자 하나당 1개, 일반적인 한자/한글 음절 하나당 1개). 하지만 U+FFFF를 넘는 코드 포인트는 서로게이트 쌍(surrogate pair)이라는 두 개의 코드 단위로 인코딩됩니다. 그래서 😀 같은 이모지는 읽는 사람이 한 글자로 보더라도 .length === 2로 나옵니다. 사람이 실제로 인식하는 단위인 그래핌 클러스터(grapheme cluster) — 한글 자모 조합이나 ZWJ(폭 없는 결합자)로 이어진 이모지까지 포함 — 를 세려면 grapheme 단위의 Intl.Segmenter를 사용해야 합니다.

단어는 정규식 /\s+/(하나 이상의 공백 문자)로 분할한 뒤 빈 세그먼트를 제외하고 셉니다. 줄은 \n으로 분할합니다. 바이트는 문자열을 UTF-8로 인코딩하는 TextEncoder에서 가져옵니다. ASCII는 1바이트, 라틴-1 글자는 2바이트, 한글 음절은 3바이트, 대부분의 이모지는 4바이트입니다. 문장은 종결 구두점으로 분할합니다. 모든 계산은 브라우저 안에서 로컬로 이루어집니다.

사용 예

Hi 안녕 😀라는 문자열(공백, ASCII 두 글자, 공백, 한글 음절 두 개, 공백, 이모지 한 개)을 생각해 봅시다. 결과는 다음과 같습니다.

문자 수 (.length):     8   // H,i,공백,안,녕,공백,서로게이트-쌍
바이트 (UTF-8):       13   // 2 + 1 + 6 + 1 + 4
단어 (\s+ 분할):       3   // "Hi", "안녕", "😀"
줄 (\n 분할):          1
그래핌 (Segmenter):    6   // 사용자가 보는 글자 수

.length(8)와 그래핌(6) 사이의 차이를 주목하세요. 서로게이트 쌍의 두 코드 단위가 인지상 한 글자로 합쳐지기 때문에, 엄격한 .length 검사는 이모지가 포함된 텍스트를 잘못 셀 수 있습니다.

자주 묻는 질문

이모지가 왜 두 글자로 카운트되나요?

JavaScript 문자열은 UTF-16으로 저장되며 .length 속성은 보이는 기호가 아니라 코드 단위 수를 셉니다. 기본 다국어 평면(BMP) 밖의 문자(이모지 등)는 두 개의 코드 단위로 이루어진 서로게이트 쌍으로 인코딩되므로 .length가 2를 반환합니다. Intl.Segmenter 기반의 그래핌 카운터는 사용자가 한 글자로 인식하는 단위를 세므로 1을 반환합니다.

단어는 어떻게 세나요?

텍스트를 하나 이상의 공백 문자(정규식 /\s+/)로 분할한 뒤 빈 세그먼트를 제외하고 셉니다. 단어에 붙은 구두점은 제거하지 않으므로 hello,는 한 단어로 카운트됩니다.

문자 수와 바이트 수의 차이는?

문자 수는 문자열의 .length로 UTF-16 코드 단위를 셉니다. 바이트 수는 TextEncoder로 UTF-8 인코딩했을 때의 크기를 측정합니다. ASCII 글자는 1바이트, 한글 음절은 보통 3바이트, 이모지는 대개 4바이트입니다.

줄은 어떻게 세나요?

입력을 줄바꿈 문자(\n)로 분할하여 셉니다. 빈 입력은 0줄, 후행 줄바꿈이 없는 한 줄 입력은 1줄로 나옵니다.

제 텍스트가 서버로 전송되나요?

아닙니다. 모든 카운트는 입력하는 즉시 브라우저에서 로컬로 계산됩니다. 텍스트는 기기를 떠나지 않으므로 초안, 메시지, 민감한 내용에도 안전하게 사용할 수 있습니다.
